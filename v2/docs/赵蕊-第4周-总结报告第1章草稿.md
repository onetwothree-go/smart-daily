## 1.1 项目概述与两阶段路线

本项目为「智能日报生成器（Smart Daily Report Generator）」：聚合 GitHub 提交、飞书任务、飞书群消息等工作记录，按成员生成个人日报与团队日报，经多通道推送并落库。全组 4 人（杨佳莹、于悦、方赫、赵蕊）承担需求分析师、架构师、开发工程师、测试工程师、配置管理员五个角色，按周轮换（出处：`docs/小组角色分工与轮换表.md` §一）。

项目分两个阶段推进：

- **阶段一（v1，第 1–2 周，SDD 流程）**：走需求 → 设计 → 任务分解的规范路线，产出 proposal 0.4.2（2026-11-09 定稿，出处：`v1/specs/design.md` 文档头引用行）、design 0.6（含推送五态、退出码契约与 ADR-104，出处：`v1/specs/design.md` 文档头）、tasks 0.1.x，并完成 v1 实现。v1 复盘沉淀三个已知坑：采集器吞异常返回空列表、`pushed = any(ok)` 把部分送达判成功、身份映射大小写不同规（出处：`v2/README.md` §4）。
- **阶段二（v2，第 3 周起，Superpowers 流程）**：从零重写，只带设计结论不带 v1 代码（零复制红线，出处：TK-V2-000 验收②「全文无 v1 代码块」、验收④「`grep -r "import smart_daily" v2/` → 0 命中」），以 tasks.md 的任务驱动 TDD 红绿重构（初始 36 条，第 4 周变更单后增至 40 条）。工程基线四项决策为 ADR-101~104：httpx 直连无 ORM、sqlite3 + UNIQUE 约束幂等写入、异常驱动降级由编排层统一判定、Actions 触发的实时提醒契约（出处：`v2/README.md` §1）。截至 2026-11-26，v2 全量测试 **314 passed**、ruff check 与 format 双清、CI 门禁绿（出处：`v2/docs/赵蕊-第4周周报告.md` §二、dev 分支 run 记录；267 passed 为 2026-11-24 修复前的时点数字）。
