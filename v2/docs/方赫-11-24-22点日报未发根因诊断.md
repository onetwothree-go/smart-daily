# 11-24 22:00 日报未发送 · 根因诊断（第 4 周运维留痕）

> 日期：2026-11-24 ｜ 撰写：方赫 ｜ 状态：✅ 本人已核验（2026-11-24）
> 触发：用户「10 点那次没发，你能给我找到原因吗」。本文只做根因定位，不改任何代码/配置；结论均附可复现证据。

## 一、现象

22:00 计划任务 `SmartDaily-2200` 调 `v2/scripts/run_daily.ps1` 跑日报，结果 **未发送**（飞书群无通知、无落库）。日志 `v2/data/logs/daily-2026-11-24.log` 记录：

```
采集或落库失败：all_sources: github: main: 请求失败：[SSL: UNEXPECTED_EOF_WHILE_READING] ...; dev: 同;
feishu_task: token 接口错误 code=21001：Access denied due to platform policy;
feishu_chat: 凭证未配置：FEISHU_CHAT_ID
[2026-11-24 22:00:24] mode=REAL exit_code=1
```

## 二、直接原因（机制层）

`collect_with_fallback`（`v2/src/smart_daily_v2/sources/fallback.py`）是**异常驱动降级**：按顺序跑源，**第一个成功的源即返回**；三个源全抛 `SourceUnavailableError` 才在末行抛 `AllSourcesUnavailableError` → CLI 捕获 → `exit 1`（`cli.py` L157）。

22:00 三个源全失败：

| 源 | 失败原因 | 性质 |
|---|---|---|
| github | main/dev 均 `SSL UNEXPECTED_EOF` | 网络/代理链路 + API 限额（见第三节） |
| feishu_task | `tenant_access_token` 接口 `code=21001`（platform policy 拒绝） | 飞书应用权限/平台策略，持续性问题 |
| feishu_chat | `FEISHU_CHAT_ID` 未配置 | 配置缺失，持续性问题 |

全失败 → 无 `WorkItem` → 不落库 → 编排层根本没走到 `dispatch`（通知在 `run()` 后半段），所以飞书群没有收到任何推送。**"没发"不是通知环节坏了，是采集环节先断了、通知从未被触发。**

## 三、根本原因（github 源为何 SSL EOF）

"Git 号掉下来了"不是账号密码失效，而是 **GitHub API 匿名限额耗尽 + 系统代理链路不稳** 叠加：

1. **匿名 API 限额打爆**：经系统代理实测 `GET https://api.github.com/rate_limit` → `limit 60 / used 60 / remaining 0`（匿名上限 60/h）。22:00 时刻该窗口已耗尽。
2. **重置时间恰好在之后**：`reset=1795530070` → 北京 **22:21:10**。即 22:00 失败、22:17 补跑时匿名限额都还没恢复。
3. **系统代理链路不稳**：WinINET 系统代理指向 `127.0.0.1:65532`（进程 `nano.exe`，11-23 21:44 启动），实测经它访问 github 同时出现 `403 rate limit exceeded` 与 `SSL UNEXPECTED_EOF`——与 22:00 日志里 github 的报错同类。Clash（7897）进程 11:54 起一直存活、不是它崩了。
4. **为何 22:17 补跑成功**：补跑走 `GITHUB_TOKEN` 认证请求（认证限额 5000/h，不受匿名 60 限制）+ **清代理直连**（绕开 65532 的 SSL EOF），故 `--source github` 一次成功、落库 34 条、退出码 0（全通道推送成功）。

## 四、结论

- **主因**：22:00 的 github 采集因「匿名 API 限额耗尽 + 系统代理 65532 链路 SSL EOF」失败；
- **叠加因**：feishu_task（21001）、feishu_chat（无 CHAT_ID）两个源本就不可用；
- **机制因**：`all_sources` 任一源单独失败可降级，但三源全失败即整体失败，通知环节不被触发。
- **不是**：GitHub 账号/token 失效（token 认证请求 22:17 仍可用）、Clash 进程崩溃（11:54 起一直存活）、推送代码本身的问题（补跑同码成功）。

## 五、待办（不在本次范围，登记不擅改）

1. `v2/scripts/run_daily.ps1` 的 `--env-file .env` 已含 `GITHUB_TOKEN`，但 22:00 匿名限额耗尽说明当时请求**未带 token 或 token 未生效**——需核对计划任务运行账户能否读到 `.env` 的 token（属配置侧，待查）。
2. feishu_task 的 `code=21001` 与 feishu_chat 的 `FEISHU_CHAT_ID` 缺失是持续配置问题；若 daily 只需 github 源，可考虑计划任务改 `--source github`，避免坏源拖累（改配置属他方职责，本人不擅动，登记 ☐）。
