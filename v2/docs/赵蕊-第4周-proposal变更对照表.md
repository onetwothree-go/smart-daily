## 六、第二轮评审注意点（预答）

1. **「为什么只落条目不拍口径？」** → E1–E5 的冲突点（呈现形态/聚合 vs 1:1/实时提醒 vs 手动触发）全部是架构契约或组内裁决项，需求侧预写即越权；proposal 给足冲突点、前置与建议案，方赫在评审通过后拍 design。
2. **「S14 为什么登记了又说本版不做？」** → 范围条目登记 ≠ 开工承诺；S14 有三重前置且与推送链全链冲突，若不登记则老师方向在需求文档缺位（架构师无法拍 design），登记并标前置是两全。
3. **「迟到分类能不能直接做？」** → 不能默认做：2A（2026-11-25 组内裁决）白纸黑字仅出勤状态，迟到需时刻阈值比较属扩展推导，须重裁 2A（I30 ①）；全勤/缺卡可从出勤状态直接推导，初版可做。
4. **「C12 为什么没有具体断言？」** → 第 3 周已裁定验收标准必须可测，但断言口径依赖 #7–#11 裁决；C12 以三条不变量承担可测底线，细分断言在 design 契约定稿时逐条建立并另行过评审。

## 八、第三轮评审注意点（预答）

1. **「脱敏是不是倒退了 2A？」** → 不是。2A 是隐私**上限**（最多到出勤状态），实现比上限更严（连状态都不进正文）是收紧不是突破；C11 ④ 的 1:1 对账所需的完整状态仍在 `detail` 落盘，审计链不受影响。
2. **「为什么改 904 验收⑤字面而不是改代码？」** → 开发侧已按互斥契约改用例（`7db0172`），规范字面是旧口径残留；规范跟随已定案的 CLI 契约修订属需求侧职权，且这正是 DEF-11 登记时「移交需求侧」的约定动作。
3. **「S11 甲乙两案（呈现增强）与脱敏冲突吗？」** → 不冲突：脱敏是**现行 S10/C11** 的呈现定案；S11 的「加栏/摘要行」是第二层增强，其口径仍挂开放问题 #7 待评审——若 OP-7 裁决乙案「独立考勤栏」，须按 C12 不变量① 先修订 C11 并过评审。
4. **「B#5 的 scope 字面回填了吗？」** → design §4-2 的英文 scope 字面归方赫（文档作者），本轮以「联调读出 4 条」作为权限实锤登记进 U13；字面回填不阻塞勾销，仍请方赫补。
