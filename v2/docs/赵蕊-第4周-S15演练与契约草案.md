## 2. CLI 契约草案（请方赫按 #11 定案）

### 2.1 命令形态

```text
python -m smart_daily_v2.cli --attendance --member <姓名> --month <YYYY-MM> [--mock | --source feishu_attendance]
```

`--attendance` 与 `--list`（历史日报查询）并列且**互斥**，同时出现按参数错误处理（exit 2）。

### 2.2 参数

| 参数 | 必填 | 取值 | 说明 |
|---|---|---|---|
| `--attendance` | 是（进入查询模式） | flag | 不加则维持既有行为（跑日报 / `--list`） |
| `--member` | 是 | 成员姓名（`normalize_key` 后比对） | 缺省 → exit 2 |
| `--month` | 是 | `YYYY-MM`（两位月 01–12，正则校验） | 缺省或格式错 → exit 2；闭区间 [月初 00:00:00, 月末 23:59:59.999999] |
| `--mock` | 否 | flag | 走无凭证夹具（含 2 条考勤样例），离线可复现 |
| `--source` | 否 | 仅 `feishu_attendance` | 其它源 → exit 2；不传则默认考勤源 |

### 2.3 输出格式（TSV，与 `--list` 同风格）

```text
日期	成员	状态	时刻	record_id
2026-11-18	甲	正常	08:55	mock-att-001
```

- 列固定 5 列，按打卡时刻**升序**（月度对账看表习惯；与 `--list` 倒序不同，见 §5 待定 ④）
- 无记录：stdout 为空、stderr 提示「`<月份>` 该成员无考勤记录」、exit 0（与 `--list` 空结果一致，便于管道）
- 隐私：不输出定位、WiFi、设备号，**不输出状态以外的考勤明细**（I30 / 2A 上限）

### 2.4 退出码（沿用既有四值表，不新增）

| 码 | 场景 |
|---|---|
| 0 | 查询成功（含无记录） |
| 1 | 采集失败（凭证缺失、接口错误）、或真实源下成员映射未配置 |
| 2 | 参数错误：缺 `--member`/`--month`、月份格式错、源不匹配、`--attendance` 与 `--list` 同用、成员不在映射表内 |

**不新增退出码**是刻意选择：既有表已被 `--help` 逐字展示且被 504 用例锁住，新增码会牵动 `test_cli_usability` 与文档同步义务（#21）。

### 2.5 与 #21 的关系

S15 **不改** 504 的「四项→五项同步」留痕义务，也不改既有两个用途（跑日报 / 查历史日报）。查询子命令是第三个用途，独立于 #21 已确认的 CLI 契约。

## 3. 实现落点（现场改造 15 分钟要讲清的链路）

| 层 | 落点 | 改动 |
|---|---|---|
| 参数层 | `cli._build_parser()` | 加 `--attendance` / `--member` / `--month` 三个参数 |
| 校验层 | `cli._month_bounds()` | 正则校验 + 次月月初减 1 微秒算月末（不写 28/29/30/31 分支） |
| 查询层 | `cli._attendance_query()` | 选源 → `collect(since, until, author)` → `normalize_key` 二次过滤 → 排序输出 |
| 采集层 | `sources/attendance.py` | **零改动**（复用 TK-V2-901 已验收的 `FeishuAttendanceSource`） |
| 存储层 | `storage.py` | **零改动**（查询只读，不落库、不碰日报历史表） |

讲解顺序建议：`--help` 四值退出码表 → `_build_parser` 三个新参数 → `_month_bounds` 闭区间 → `_attendance_query` 两张前置护栏 → 输出五列 → 跑 `--mock` 与错误路径各两条。

## 6. 现场改造 15 分钟脚本（答辩用）

1. **30 秒定位**：proposal S15 一句话 + 为什么它是「已通过但未实现」的唯一一条（#11）。
2. **2 分钟讲既有链路**：`cli` → `sources/attendance.py`（零改动复用）→ `WorkItem` → 输出，说明为什么存储层不动（查询只读、`work_items` 表本阶段只建不写）。
3. **3 分钟讲参数与校验**：`_month_bounds` 为什么用「次月减 1 微秒」；为什么沿用四值退出码而不新增。
4. **5 分钟现场改**：把「按人查」扩成「按人按状态筛」（加 `--status`），跑红 → 绿；或把输出加 `--json`（老师若要求换一种呈现）。
5. **3 分钟讲发现的坑**：`author` 形参未生效（①）、映射缺失会被伪装成空结果（②）——这两条是「照着文档写会踩、跑一次才发现」的实证。
6. **1 分钟收口**：契约草案已交方赫定案（#11），本分支不合入、不代改 design/tasks。
