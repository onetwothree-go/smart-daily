## 1. 逐条预判（5 项）

> 说明：每条的"架构师角色"都写的是**等 proposal 落地后才能拍**的口径。现在它们一律是 ☐，因为需求侧还没在 proposal 加条目——架构师不能在需求文档缺位时先拍设计。

### E1 · 个人日报加一栏：打卡时间 + 考勤状态，与工作记录并排

- **现行冲突**：C11 定案考勤是"条目行"（`format_item()` 同源、badge 强制「考勤」、状态内嵌 `detail`）。"单独开一栏"是**另一种呈现**，两者只能选一个。
- **若要做的前置**：proposal 先定呈现口径（加栏 vs 条目行）→ C11 验收判据同步 → design §3/§5 修订 → `generator.py::build_personal_report` 改表头。
- **架构师能拍什么**：呈现口径属架构契约（生成层），但须等 proposal 加了范围条目后才能拍。
- **影响面**：generator.py、C11、tasks 新任务、既有 273+ 用例中日报版式断言。
- **状态**：✅ 架构师已拍乙案方向（2026-11-26，见 §5；个人日报独立考勤块 + 工作记录列表、无表格分隔行）；☐ 待赵蕊修订 proposal C11① 并过全组评审 → 方可进 design / tasks / 代码。团队日报本轮不动。

### E2 · 团队日报加"出勤一览"：谁全勤 / 迟到 / 缺卡

- **现行冲突**：这是**聚合统计**，与 S10/C11「1:1、不聚合、不摘要」正面冲突。更敏感的是——组内 2026-11-25 刚裁决 **2A「仅出勤状态、不算迟到早退时长」**，"全勤/迟到/缺卡"分类恰好踩在这条隐私边界上。
- **若要做的前置**：proposal 先加新范围条目（S11?）与新成功标准（C12?），明确聚合口径与隐私边界（是否突破 2A，须组内重裁）→ design §5 增聚合契约 → tasks 新任务。
- **架构师能拍什么**：聚合口径、隐私红线属架构契约，但必须在 2A 被重新裁定之后。
- **影响面**：generator.py::build_team_report、C11、C1/G1 判据、隐私合规。
- **状态**：☐ 待需求侧落条目 + ☐ 待组内重裁 2A。

### E3 · 缺卡自动提醒：接 `notify_push`，到点没打卡就推一条

- **现行冲突**：**五项里风险最高**。design §2 白纸黑字「考勤不触发实时提醒」、§7 U6 复核结论（应送达集合 5/6 条）、404 / 605 / DEF-05 的回执口径、"推送由本人执行"的职责边界——做了这条，这些全要翻。
- **若要做的前置**：重裁 U6 → 404/605/DEF-05 应送达集合与回执全链同步 → N5/S9/C10/I24 通道边界修订 → 组内评审。
- **架构师能拍什么**：这是**纯架构裁定**，绕不开本人；但仍须 proposal 先加范围条目，不能本人直接改 design。
- **影响面**：整条推送链（应送达集合、回执、DEF-05）、U6、N5/S9/C10/I24、notify_push 通道。
- **状态**：☐ 待需求侧落条目 + ☐ 待本人裁定 U6 + ☐ 待全链同步 + ☐ 待组内评审。

### E4 · 考勤异常汇总周报：按周聚合给老师 / 组长

- **现行冲突**：超出"自然日日报"窗口；G1 计数按日、`--day` 是单日契约。
- **若要做的前置**：proposal 先加范围条目 + 新成功标准（周报的周期、聚合口径、收件人、触发日）→ design 增"周聚合"契约 → tasks 新任务。
- **架构师能拍什么**：周期 / 窗口 / 收件人契约由本人定，但须等需求侧落地。
- **影响面**：新生成路径、新验收标准、收件人配置。
- **状态**：☐ 待需求侧落条目 + 组内评审。

### E5 · 按人按月查考勤：`--list` 之外加查询命令

- **现行冲突**：超出 #21 已确认的 CLI 契约（source 四项 + 退出码表 + `--list` 按日查询），属**新 CLI 子命令**。
- **若要做的前置**：proposal 加范围条目 → design 定新子命令规范（参数、输出格式、退出码）→ tasks 新任务；#21 留痕里"第五源落地后四项→五项同步"的义务不受影响、不自动覆盖。
- **架构师能拍什么**：CLI 契约由本人定（与 #21 同类），但须等需求侧落地。
- **影响面**：cli.py、#21 留痕、退出码表。
- **状态**：☐ 待需求侧落条目 + 组内评审。
