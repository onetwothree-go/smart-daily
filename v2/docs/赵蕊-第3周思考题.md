### 第 1 问 · 任务粒度过大和过小分别会出什么问题？

**结论先说**：粒度过大，验收标准写不出三要素，红绿循环退化成「跑一遍全量绿」；粒度过小，交付物失去独立可验证性，只剩形式上的勾选。本组的尺子写在 tasks.md 里——**一条任务 = 一个可验证交付物 = 一次提交**。本问从测试 + 配置侧举证，与于悦（需求侧）、方赫（开发侧）的两份已交稿件互补。

**第一，过大首先毁掉的是测试侧的失败判据。** 607（C1–C10 逐条核对表与覆盖率归档）如果按「归档全部质量数据」一个大任务立项，验收标准只能写成「归档完成」——没有输入、输出、阈值，红绿循环无从谈起。实际拆开后它的验收是具名的：覆盖率报告、ruff 输出、CI run 链接逐条落 `v2/docs/testing/证据/`，每一条都能指到文件和命令。

**第二，过大还会让「部分完成」无法被观测，进度维护记录只能记「上游自报绿」。** 第 3 周于悦的进度维护记录里，方赫连交 9 条（301–304、401–404、601）每条都能独立判 🟩 待核对——因为每条对应一个独立交付物；如果这 9 条合成「实现采集与推送层」一条，记录只能写「进行中」，谁也说不清卡在哪。粒度过大的任务在统计上永远只有 0% 和 100% 两档，中间状态全部丢失。

**第三，过小则交付物失去独立可验证性。** 604（条目行格式与 1:1 计数）依赖 601 夹具和 304 生成器，若再拆成「表头行」「条目行」「占比列」三条，任何一条单独都验收不了——它们共享同一个生成函数，拆分只增加交接与回归成本。P2 三个采集器能并行，恰恰是因为粒度切到了文件边界（`github.py` / `feishu_tasks.py` / `feishu_chat.py` 互不重叠）；v1 曾把三个飞书功能塞进一个文件导致只能串行，就是粒度与文件边界错位的反例。

**第四，粒度过小还有一个配置侧特有的症状：提交噪音淹没信号。** 一条任务一次提交是纪律，但把一次提交能完成的改动拆成多次，CI run 会成倍增加而每条都只验证半个改动；我维护 CI 门禁归档时按「一次 push 对应可复核的完整语义」筛选 run 链接，过碎的提交历史让「这条 run 对应哪条任务」的对账成本显著上升。

**所以**：判粒度的三条尺子是——验收标准能否写全「输入/输出/阈值」三要素、能否对应一次独立提交、交付物能否单独指认。36 条（现 40 条）按七段链路排布并标注并行组，就是卡在这三条的交集上。

### 第 2 问 · 从验收标准生成测试与从代码生成测试，哪种更能发现规范缺陷？

**结论先说**：从验收标准生成测试更能发现规范缺陷——包括**规范自身的缺陷**。从代码生成测试只能证明「实现与实现一致」，而本组第 3 周 607 重写和第 4 周 DEF-05 红用例两次证明：对着标准看，实现和规范的问题都会浮出来。

**第一，607 重写是一次「验收标准优先」的实证。** 原核对表用 `-k "C1 or C2"` 跑一遍得到 1 条通过就判 ✅，数据看着绿，其实是选择器只匹配了 1 个用例——这是典型的「证据迁就结论」。重写时我按 tasks/验收矩阵的 10 个真实 nodeid 逐条对照 C1–C10 判定，结果是 ✅4 / ⚠️3 / ❌2 / ⏭1，通过率 44.4%。**规范没有变，变的是「从标准出发」这个视角**——C5、C10 的未达成就是这次重写暴露的，从代码生成的测试永远不会主动告诉你这两条标准还没落地。

**第二，从代码生成测试会把实现的偶然行为固化成「预期」。** 第 4 周 DEF-05 红用例（`a4d3630`）是反过来的做法：先从 proposal/契约语义读出「无收件人必须留 `no_recipient` 标记」，再写用例——它当场失败（1 failed / 267 passed），暴露实现里 `error` 字段是空串。如果当时从代码生成测试，生成的断言只会是 `error == ""`，用例永远绿，缺陷不复存在——直到有人发现收不到任何失败原因。**规范缺陷（契约没写清字段约定）和实现缺陷（少补标记）是同一次失败暴露的**，这正是「从标准生成」的价值：它同时审标准和审实现。

**第三，「先有可测标准、才有测试」的顺序不能反。** U1 降级链冲突（proposal C8 vs README §2）在标准被 K1 裁定收紧之前，无论怎么写测试都绕不开两套口径；先由架构师裁定三分支语义，602（降级注入用例）才写得下去。这说明从验收标准生成测试有一个前置义务——**测试侧要参与把标准审到可测**，否则拿到的标准本身就是缺陷。

**所以**：从代码生成测试回答「代码是不是这样跑的」，从验收标准生成测试回答「我们是否在做对的事」。前者永远绿得心安理得，后者会疼，但疼的地方就是缺陷所在。
