## 3. 数据模型增量

1. **`WorkItem` 八字段建议保持不变**：`record_id / source / member / kind / title / detail / occurred_at / local_day` 已能承载考勤（出处：`models.py:31–42`）。是否扩字段（如 `attendance_status`）→ ☐ 待确认；建议状态放 `detail`，避免改 frozen dataclass 引发全链回归。
2. **不新增 `AttendanceEntry` RawRecord 型（架构师建议）**：v2 现行三型 `CommitEntry/TaskEntry/MessageEntry` 只服务于 `normalize()` 的类型映射（`models.py:77–81`），而三个 v2 采集器已直接返回 `WorkItem`。新增第四型会引入「考勤到底归一化一次还是两次」的新歧义（G7 已禁止二次归一化）。若组内决定新增，则须同步扩展 `_SOURCE_BY_TYPE` 与 `normalize` 的 `isinstance` 白名单。→ ☐ 待裁定。
3. **`source`/`kind` 取值候选**：`source="feishu_attendance"`、`kind="attendance"`（与既有 `feishu_task`/`task` 命名同构）。→ ☐ 待确认（须与 C11 类型标签「考勤」对齐）。
4. **归属日**：沿用 `local_date(occurred_at)`（东八区 `LOCAL_TZ`），自然日窗口 `[当日 00:00, 次日 00:00)`；跨天记录一律归打卡时刻所在日。与 v2 `orchestrator.run()` 现有窗口和 `local_date` 二次过滤一致。→ ✅ 沿用基线，无需新裁定。
5. **`record_id` 对账缺口**：C11 要求「考勤条目带 `record_id` 可与原始记录 1:1 对账」，但现行 `format_item()` 只输出 `| HH:MM | badge | 内容 |`（`generator.py:55`），**日报文本不带 `record_id`**，且 `daily_reports` 表也不存条目明细。三条候选：① 把 `record_id` 写入 `detail` 随日报落文本；② 新增条目明细表；③ C11 改为只校验归一化层的 `WorkItem.record_id`（不校验日报文本）。→ ☐ 待组内裁定（架构师建议 ①，改动面最小；不自行改 C11）。
6. **SQLite**：建议不新增表、不改 `daily_reports` 结构（基线 2.3 冻结）。若选上条②，须另出 design 增补并过评审。→ ☐ 同上。

## 5. 生成层增量（3.2）

1. **条目行格式字面冲突（重要）**：proposal C11 写「行格式 `- [HH:MM]（考勤）标题` 与 G4 逐字一致」；但 v2 现行 `format_item()` 输出的是 **Markdown 表格行** `| HH:MM | \`badge\` | 内容 |`（`reports/generator.py:46–55`），二者不是同一格式。按「两处不一致即缺陷」登记，候选：① 以 v2 现行表格行为准，proposal C11 字面由需求侧同步修订（架构师建议，避免动既有 C4/G4 与 273 条测试）；② 为考勤单独开列表行格式（会破坏日报版式统一，不推荐）。→ ☐ 待组内裁定，**本文不代改 proposal**。
2. **类型标签**：`_KIND_LABELS` 建议增 `"attendance": "考勤"`；同时 `_type_badge()` 会优先匹配 conventional 前缀 `^([A-Za-z][A-Za-z0-9_-]*)\s*:`（`generator.py:11–17`），考勤标题一旦含 `xxx:` 就会显示英文徽标而非「考勤」。建议对 `kind=="attendance"` 强制返回「考勤」。→ ☐ 待确认。
3. **`HH:MM` 取什么时刻**（proposal §7-3 点名方赫）：候选 A = `occurred_at` 打卡时刻（与 `WorkItem` 同源、可追溯，架构师建议）；候选 B = 22:00 汇总时刻（无信息量、且与既有三源口径不一致）。时区统一按 `LOCAL_TZ` 转换（`format_item` 已实现）。→ ☐ 待组内。
4. **无记录成员**：不生成空考勤条目，遵守 C8「今日无工作记录」语义（proposal C11 ②）。→ ✅ 与现行 `group_by_member` 行为一致。
5. **1:1 不聚合**：原始考勤记录数 = 考勤 `WorkItem` 数 = 日报考勤行数；同一 `record_id` 不重复计数。→ ✅ 沿用 I7/ADR-102 幂等口径。

## 6. 非功能性约束与 ADR 候选

- **个人信息最小化（硬约束）**：仅采集出勤状态；**不采定位、打卡图像、设备信息**；如需扩字段须另走变更（承接 N3 原排除理由，转为 FR-KQ1 约束①）。
- **凭证红线**：沿用设计 5.2——凭证走环境变量、绝不入仓、不进 `MEMBER_EMAILS`。
- **频控**：沿用 5.1 飞书限频口径；考勤接口若单独计数，需在 tasks 9xx 写明退避策略（不重试由 ADR-103 约束）。
- **ADR-105（候选，待评审）**：考勤采集最小化与通道隔离。背景＝N3 解除但隐私理由不得消失；决策＝仅出勤状态进日报、独立采集支路、失败留痕不中断、不新增推送通道；后果＝C11 可测且不影响 1.4/3.4/DEF-05；备选项＝并入 fallback 链（§4-3 候选 B，需重裁）。→ ☐ 待全组评审，**不替代 ADR-101~104**。
