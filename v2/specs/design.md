## 3. 数据模型增量（架构师裁定，待评审追认）

1. **`WorkItem` 八字段保持不变**：`record_id / source / member / kind / title / detail / occurred_at / local_day` 已能承载考勤（`models.py:31–42`）；出勤状态写入 `detail`，不扩 frozen dataclass、不引入全链回归。✅ 架构师定案。
2. **不新增 `AttendanceEntry` RawRecord 型**：v2 三型 `CommitEntry/TaskEntry/MessageEntry` 只服务于 `normalize()` 的类型映射（`models.py:77–81`），三个 v2 采集器已直接返回 `WorkItem`；新增第四型会引入「归一化一次还是两次」的新歧义（G7 禁止二次归一化）。✅ 架构师定案。
3. **`source` / `kind` 固定取值**：`source="feishu_attendance"`、`kind="attendance"`（与既有 `feishu_task`/`task` 同构；生成层标签「考勤」见 §5-2）。✅ 架构师定案。
4. **归属日**：沿用 `local_date(occurred_at)`（东八区 `LOCAL_TZ`），自然日窗口 `[当日 00:00, 次日 00:00)`；跨天记录归打卡时刻所在日。✅ 沿用基线。
5. **`record_id` 对账**：采用**方案 ①——把 `record_id` 写入 `detail` 随日报落文本**。理由：现行 `format_item()` 只输出 `| HH:MM | badge | 内容 |`（`generator.py:55`），日报文本与新表都不带 `record_id`；内嵌 detail 改动面最小且满足 C11 的 1:1 对账。方案 ②（新增条目明细表）不采用（触碰基线 2.3 冻结）；方案 ③（只校验归一化层）不采用（不满足 C11 字面）。✅ 架构师定案，待评审追认。
6. **SQLite**：不新增表、不改 `daily_reports` 结构（基线 2.3 冻结）。✅ 架构师定案。

## 5. 生成层增量（3.2，架构师裁定，待评审追认）

1. **条目行格式冲突定案**：proposal C11 写「行格式 `- [HH:MM]（考勤）标题` 与 G4 逐字一致」，但 v2 现行 `format_item()` 输出的是 **Markdown 表格行** `| HH:MM | \`badge\` | 内容 |`（`reports/generator.py:46–55`）。**采用现行表格行**（考勤条目无特殊行格式），避免动 C4/G4 与既有 273 条测试；**proposal C11 字面须由需求侧同步修订**（评审必办，本文不代改 proposal）。不采用「为考勤单开列表行」（破坏版式统一）。✅ 架构师定案，待评审追认。
2. **类型标签定案**：`_KIND_LABELS` 增 `"attendance": "考勤"`；因 `_type_badge()` 优先匹配 conventional 前缀 `^([A-Za-z][A-Za-z0-9_-]*)\s*:`（`generator.py:11–17`），对 `kind=="attendance"` **强制返回「考勤」**，避免标题含 `xxx:` 时显示英文徽标。✅ 架构师定案。
3. **`HH:MM` 取 `occurred_at` 打卡时刻**（与 `WorkItem` 同源、可追溯；不取 22:00 汇总时刻）；时区按 `LOCAL_TZ` 转换（`format_item` 已实现）。✅ 架构师定案，待评审追认（proposal §7-3 原点名「方赫 + 组内」，组内可评审翻案）。
4. **无记录成员**：不生成空考勤条目，遵守 C8「今日无工作记录」语义（proposal C11 ②）。✅ 与现行 `group_by_member` 一致。
5. **1:1 不聚合**：原始考勤结果数 = 考勤 `WorkItem` 数 = 日报考勤行数；同一 `record_id` 不重复计数。✅ 沿用 I7/ADR-102。
