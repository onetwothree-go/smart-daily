## 3. 功能需求：FR-KQ1（飞书考勤数据采集）

| 项 | 内容 |
| --- | --- |
| 需求编号 | FR-KQ1（考勤=KaoQin，避免与既有 F/Q/P/A 编号体系混淆） |
| 涉众 | 组内 4 名成员（数据主体）、组长（团队日报读者）、指导教师（外部收件人）、需求分析师/架构师/开发/测试（实现与验收） |
| 触发 | 每天 22:00 本机手动触发汇总时，与 GitHub/飞书任务/群消息同批采集（不引入新的触发方式，遵守 I4/N8「手动触发」口径） |
| 输入 | 飞书开放平台考勤接口返回的当日考勤记录（成员、日期、出勤状态） |
| 输出 | ① 归一化考勤条目（`record_id` 内嵌 `detail` 可对账）；② 个人日报与团队日报中的考勤条目行（行格式为 v2 现行 Markdown 表格行，badge 标签「考勤」，版式与其他条目统一）；③ 采集失败时的留痕（错误信息进推送明细/日志，主流程不中断） |
| 约束 | ① **个人信息最小化**：仅采集出勤状态，不采集定位、打卡图像等明细（对应 N3 原排除理由的合规底线；如需扩字段须另走变更）；② 凭证不入仓（沿用 §5 红线）；③ 1:1、不聚合、不摘要（沿用 I7）；④ 与实时提醒通道无关（S9 口径不变） |
