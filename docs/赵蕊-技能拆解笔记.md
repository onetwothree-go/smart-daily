## 正文（约 200 字）

**触发描述**在 `SKILL.md` 的 frontmatter：`Use when executing implementation plans with independent tasks in the current session`。一句话只限定条件、不含步骤——"有计划 + 任务松耦合"两条同时命中才挂载，不命中则让位给 `executing-plans`。描述即路由。

**工作步骤**写在 `SKILL.md` 正文：Setup 建工作区与 `progress.md` 台账 → 每任务派一个新 implementer 子代理（隔离上下文，不继承主会话历史）→ 处理回执 → 双维度评审（规范符合性 + 代码质量）→ 不过进 fix loop → 全部完成后做一次整支线终审。主干只写"做什么、什么顺序"。

**三要素**分工明确：`SKILL.md` 是唯一入口与索引；`references/` 七篇承载长尾情形（预检、批量、无法从 diff 验证、断点续跑、终审），按需读取以避免主文件膨胀；`scripts/` 把易错动作固化为可执行件——`task-brief` 从计划抽单任务原文、`review-package` 生成带上下文的评审包、`sdd-workspace` 定工作区路径，都是"别让模型手搓路径与 diff"。

## 一句话结论

**入口写条件、正文写主干、references 写分支、scripts 写易错动作**——四层各管一件事，这是本技能可维护的原因，也是我们 `docs/` 分层可以借鉴的地方。
