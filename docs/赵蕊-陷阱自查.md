我过去用 AI 主要做环境配置和项目开发：给 Claude Code 接智谱、硅基流动的模型，在 `D:\智慧景区` 项目上干活。对照第 1 章才发现五大陷阱全踩了。

1. **不可审查（最疼）**：AI 生成的 `ANTHROPIC_BASE_URL` 多写了一层 `/v1`，没实测就落盘，跑起来报"模型不存在"，我差点照着报错去换模型——逐层排查才发现请求被拼成了 `/v1/v1/messages`。当时只验收"能不能出字"，没人审配置本身。

2. **需求蒸发**："要在 Claude Code 里用上 100 万上下文"这条需求只活在一轮对话里，最后落成 `settings.json` 里的一个参数 `1000000`。为什么是这个数、对应哪个模型的能力，任何文档都没写，过两周连我自己都讲不清。

3. **不可复现**：为了绕过 Steam++ 对 github.com 的本地证书拦截，把它的根证书合并进本地 CA 包并写进了 git 全局配置——换台电脑或卸载 Steam++ 就报证书错误。改了什么、为什么改，没有留痕，要靠翻聊天记录还原。

4. **上下文漂移**：两个 GitHub 账号并行——提交作者是 A 号、登录推送是 B 号，PR 合并后贡献者列表里查不到自己，折腾半天才发现两个身份早已分叉。

5. **不可维护**：`D:\智慧景区` 根目录混进 6 个无关的未跟踪文件（别的课设 doc、数据库设计图），AI 一句 `git add .` 险些把无关文档推进组仓——项目边界全靠人肉记忆。

这周靠规范接住：配置改动先实测再落盘，密钥一律走 `.env` 不进对话不进仓库，AI 的产出按四色清单留审查记录。
