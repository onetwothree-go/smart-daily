# 方赫 · 方法切换回顾（SDD vs Superpowers）

> 第 3 周任务 1 交付物，15 分钟写完。用途：项目总结报告"过程回顾"章素材。
> 状态：**本人已确认**（2026-11-17）——内容经方赫逐句核对，确为本人观点。

阶段一采用 SDD（规格驱动开发）：先定稿 proposal / design / tasks 再写代码。优势是需求与设计白纸黑字、可追溯可签字评审，适合需求明确、需严格把关的项目；局限是文档重、改一处要联动多份，写文档时看不见真实代码，容易纸上谈兵。

阶段二切换到 Superpowers：用 TDD 红绿循环执行已定计划。优势是强制先看到失败测试再写实现、每个任务留台账、末尾"第二双眼睛"评审能抓出自己看不见的问题，适合 AI 结对的扎实执行；局限是它假设计划已想好、自身不做设计，不能单独用，且每一步都要留证、偏慢，探索性任务不适用。

适用场景：需求模糊先用 brainstorming 想清楚；需求定稿、要存档评审用 SDD；计划已定、求高质量落地用 Superpowers 的 TDD 循环。
