这周做「智能日报生成器」，从环境配置到代码几乎全程由 AI 协作，一周内把教材第 1 章的五大陷阱踩了好几个，才明白为什么必须先写规范。

**上下文漂移**最明显。我白天明确说过分工要按五个角色对应各自的产物，AI 转头就把全组的活写成我一个人的行动清单，连手册标题都变成「需求分析师作战手册」，我纠正了两次才拉回来。口头约束放在对话里会失效，不落到文件上就守不住。

**不可审查**也真发生了。11 月 3 号飞书群里那条日报，我一直当成组员的真实活动，后来查 SQLite 才发现是「张三、李四、王五」的 mock 假数据，加一个 `as@local` 的无效身份。产物没有对照标准时，我根本分不出真假。

**不可复现**同样：同一个程序，直接 `python -m` 不读 `.env`，静默降级去读本地 git 的旧记录；换成 `uv run --env-file .env` 才拿到真实 GitHub 数据。代码没变，换个启动方式结果就不同。

对照 SDD，这三条分别要由「规范即文档」「规范可执行」「规范可版本控制」接住。所以这周我先把 proposal 写清楚：范围、不做什么、能拿去测的成功标准，再让 AI 动手。
