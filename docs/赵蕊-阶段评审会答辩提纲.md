## 一、5 分钟讲稿（只讲三件事）

1. **四层不是画着好看，是让依赖方向唯一。** 编排层唯一知道"今天该做什么"；采集层只产出 `WorkItem`，不认识日报长什么样；生成层是纯函数，不碰 IO；推送层只认「文本 + 接收人」，不关心数据从哪来。**下三层互不感知**，所以任意一层可以单测、可以换实现。判据写在 `design.md` 1.2 职责表——每层都写了「**不做什么**」，比写了什么更重要。

2. **契约不是描述，是可执行副本。** 3.1 每条行为约束后面直接跟断言编号（`[9][10]`、`[12]`），写契约的时候就要回答「这条由哪个断言判」。34 项断言 2026-11-11 实跑 34/34、退出码 0（证据 `TK-701-验证脚本输出`）；39 条任务每条的验收标准都是命令或可观测输出，§12 三张覆盖矩阵逐行接住 proposal 的 S1–S9 / C1–C10 / N1–N9。

3. **规范是活的，改它有据可查。** 0.4.1 是开发评审改的（7 条），0.5 是红队 8 条改的（13 处），0.5.1 是交付自检补的（ER 附件、ADR 备选项、3.6 出站清单）。每一版都在变更记录里写清「谁依据什么改了什么、改了哪些章节」，`tasks.md` 跟着同步。**红队提的 8 条我全部采纳，但 RT-05 采的是它给的另一个方案（分层写明，不统一异常类型）**——采纳不等于照抄。

## 三、设计决策速查（每条一句判据，被问就念这句）

| 决策 | 结论 | 一句判据（被问时先说这句） |
| --- | --- | --- |
| ADR-101 | httpx 直连 REST，不引 SDK | 只有 6 个出站接口，官方 SDK 的传递依赖比业务代码还多；httpx 自带连接复用（`Client` 单例）与超时控制 |
| ADR-102 | 标准库 `sqlite3`，不用 ORM | 只有 1 张主表 + 幂等约束，ORM 带来迁移成本却换不到收益；幂等靠 `UNIQUE(report_date, member)` + upsert |
| ADR-103 | 异常驱动降级，采集器内不重试 | 采集失败是**确定性**故障（凭证缺、仓库名错），重试必然再失败，降级到下一个源本身就是最好的重试 |
| ADR-104 | 推送走 Actions，归属用 `github.actor` | 无服务器；归属直接来自事件文件，省掉一层身份映射；实测 run `42587824934` HTTP 200 / code=0 / 1.48s |
| 四层单向依赖 | 编排 → 采集 / 生成 / 推送 | 下三层互不感知，才能各自单测；生成层碰 IO 就等于把降级逻辑散成两处 |
| 双通道隔离 | 日报主线（本机 22:00）≠ 实时提醒（Actions push） | 实时提醒**不落库、不计入 G1、不计入 C7 送达**；混在一起会让「送达率」永远算不清 |

## 四、必被追问 Q&A

### A 档：一定会问（答错就崩）

| # | 追问 | 答法要点 |
| --- | --- | --- |
| Q1 | 为什么分四层？三层不行吗？ | 判据不是"看起来清楚"，是**依赖方向唯一 + 每层有独立可测边界**。反证：生成层若直接调 GitHub API，降级链就散落在两处，`SourceUnavailableError` 无处统一抛。证据：1.1 图三条边 + 1.2 职责表「不做什么」 |
| Q2 | `all([]) == True` 是怎么回事？ | 红队只说「design 写 `any()`、C7 要求全送达，两者相反」。但**只改 `any→all` 不够**：全员无邮箱时集合为空，`all([])` 照样返回 True，还是误报成功。所以我把**分母**定义出来（应送达集合三条），并要求无邮箱成员也产生 `ok=False` 记录，空集合从此不可能出现 |
| Q3 | 退出码为什么 4 个？为什么不在编排层 `sys.exit`？ | 4 个码对应 4 类判据。编排层不该决定进程生死，否则它不能被当库调用、也不能单测；映射放在 CLI。最关键的区分：`--no-notify` 是 0，「要推送但没通道」是 3——22:00 无人值守跑，主动跳过和真失败长得一样就完了 |
| Q4 | 为什么异常分两种，不统一？ | 采集失败是确定性故障→策略是**降级**；推送失败是瞬时故障→策略是**留痕待重试**。统一成一个类型，上层只能"一律重试"或"一律降级"，两种都错。红队提议统一，我采的是它给的备选方案「分层写明」（5.2 纪律 1a/1b） |
| Q5 | 团队日报为什么不走 `members.py`？ | 这是**已发生过的回归**：团队日报被当成"给某人发的"，误走接收人解析。修法不是加 `if`，是在图上物理隔断——架构图拆出独立边「团队文本 → 群渠道，不经 members.py」，1.2 职责表给 members.py 补「不服务团队日报」，3.3 加两条分发硬规则 + 反例 |
| Q6 | 34 项断言是你写的吗？ | **不是。** RT-03 判给采集层组员承接，我定的是契约条款与断言编号对齐（3.1 每条约束后跟 `[n]`），验收的是编号全覆盖，不是实现。脚本 2026-11-11 实跑 34/34、退出码 0，证据已归档 |
| Q7 | AI 参与了多少？哪些是你的判断？ | `specs/` 是**人类领地**（指导书 p12）：AI 起草，我逐条核对后才提交。变更记录每行都有撰写栏——0.1~0.4 是我 11-11 补签，0.4.1 是杨佳莹改的、她注明不代签。红队 8 条回应是我本人在自己的 Claude Code 窗口逐条写的，`ai-usage-log` 有对应记录。**答辩能追问的是判断链，不是措辞** |

### B 档：很可能问（答得上就加分）

| # | 追问 | 答法要点 |
| --- | --- | --- |
| Q8 | 39 条任务怎么证明覆盖了 proposal？ | §12 三张矩阵逐行：12.1 接 S1–S9、12.2 接 C1–C10、12.3 对 N1–N9 做**反向校验**（不做的事有没有被偷偷做）。每条验收标准必须能被命令或可观测输出判定，写不出判定方式的不进表。39 条全部标了并行组（§2.1，仅无共享文件才可并行） |
| Q9 | 报告和 specs 有两处不一致就算缺陷，你怎么保证？ | 原则：**specs 是唯一事实源，报告只能引用不能另立口径**。演示前报告升 v1.1，同步六处：版本基线（0.5.1 / 0.1.4）、G4/C4 口径、新增 5.10 出站接口清单（design 3.6 的 8 个接口）、图已入库、附录 C 补三条证据、附录 B/D 索引。冲突时改报告；只有 specs 本身错才走变更记录改 specs |
| Q10 | 为什么用 Actions 推实时提醒，不用服务器 cron？ | ADR-104：无服务器、触发点天然是 push 事件、归属取 `github.actor` 免映射。**注意边界**：Actions 只服务实时提醒支路，日报主线是本机 22:00 手动触发——ADR-104 否决了「本机计划任务」用于实时提醒，不代表主线也用 Actions |
| Q11 | 为什么 sqlite 不用 ORM？幂等怎么保证？ | ADR-102：1 张主表 + 1 个唯一约束，ORM 换不到收益。幂等靠 `UNIQUE(report_date, member)` + upsert，同日重跑覆盖不新增。反例：用 `INSERT OR REPLACE` 会连 `created_at` 一起换掉 |
| Q12 | 跨天任务算哪天？ | 归属日 = `local_date(created_at)`，只计创建日一次；`completed_at` 跨天不改归属。理由：日报回答"今天干了什么"，看的是开始时间；否则晚上提交、次日完成的任务会在两天各出现一次。TK-303 有跨天用例：`created_at=11-09T22:30+08:00` / `completed_at=11-10T09:00+08:00` 只计 11-09 |
| Q13 | `push_detail` 为什么要 `at` 和 `error` 两个字段？ | 没有 `at` 就无法判"23:59 前送达"（C7 有硬时点）；没有 `error` 就无法区分「没邮箱」「没通道」「HTTP 500」「飞书 19024」，而这四类的处置完全不同（补映射 / 配通道 / 重试 / 改关键词）。只留 `ok` 的布尔值，等于把可观测性丢掉 |
| Q14 | `MultiNotifier` 为什么删？ | 它是"一个实例管多通道"的旧设计，与本版「一实例 = 一通道 + `from_env()` 单点构造」冲突，留着后人会照抄。3.3 写了弃用声明（3 条理由）而不是删掉了事，1.2 职责表补「不提供多通道聚合」——**删设计要留痕，不然下一个人会重新发明它** |

## 六、话术三原则

1. **先结论 → 再判据 → 最后指位置**：「这条我采纳了，因为不改会误报送达成功，落在 design 3.4 五态表和不变量。」
2. **问「为什么」永远答「不这样会出什么错」**，而且用真实事故：飞书采集器吞异常返空列表导致跳过 local-git 兜底；团队日报误走接收人解析；`ts.date()` 让东八区日报差一天。这三个都是仓库里真实修过的，讲出来比讲原则有说服力。
3. **不知道就说不知道**，然后补「承接在哪个 TK / 谁负责 / 现在什么状态」。评审看的是你知不知道边界在哪，不是你什么都会。
