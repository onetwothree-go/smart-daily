## 一、统一字段说明

| # | 字段 | 填写要求 |
|---|---|---|
| 1 | 用例编号 / 名称 | 与用例图 `UC1`–`UC12` / `UCX` 完全一致；名称必须「动词 + 名词」 |
| 2 | 主参与者 / 次要参与者 | 可以是人、外部系统或时间；写清谁触发、谁受益 |
| 3 | 前置条件 | 系统可验证的状态，不写没有判据的空话 |
| 4 | 后置条件（成功保证） | 成功结束时系统必须成立的状态，尽量回指 C 编号 |
| 5 | 触发条件 | 什么事件启动本用例（如 22:00 本机手动触发 / `main`·`dev` 的 push） |
| 6 | 主成功场景 | 编号步骤 1…n，每步一句「谁做什么 → 系统回应什么」，不写实现细节 |
| 7 | 扩展与异常流 | 逐条写「条件 → 分支步骤 → 结果」；写明失败是否静默、是否允许重跑 |
| 8 | 关系（include / extend） | include = 必然发生的公共行为；extend = 有触发条件的可选分支；写清指向哪个 UC |
| 9 | 对应范围条目 / 成功标准 | 回指 proposal 的 S / C 编号；**无编号可回指 = 孤立用例，按范围蔓延处理** |
| 10 | 对应任务 / 代码证据 | 回指 `specs/tasks.md` 的 TK 编号，以及仓库内可点开的路径 |
