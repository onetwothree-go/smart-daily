#### ② G5 / C2 —— 降级不中断做到了，但「留痕」没做到（证据 E-04）

用桩注入 `SourceUnavailableError("GitHub API 返回 401")` 后，数据源正确降级到 local-git、主流程照常产出、退出码 0，但**输出里搜不到 `401`、也搜不到 `Bad credentials`，stdout 一片空白**。
根因在 `collectors/base.py::collect_with_fallback`：`errors` 列表只在「全部源都失败」时拼进异常抛出，一旦有源成功，前面失败的 `errors` 直接丢弃，没有任何打印或日志。design ADR-103 写的是「故障原因留痕（errors 聚合）」，实现只兑现了一半。
**修复建议（一行）**：`except` 分支里补 `print(f"[source] {src.name} 不可用：{exc}")`，或接入 logging 后写 `logger.warning`。修完重跑本条即可改判。
**局限**：真实 401 路径未验证——本机 hosts 把 `api.github.com` 指向 127.0.0.1，TLS 被本地中间人接管，Python 报 `CERTIFICATE_VERIFY_FAILED`。本轮改用注入系统证书库（truststore）后 GitHub 采集已可正常出数据，但 401 需假 token + 真实往返才能复现，未单独执行。

**改判（2026-11-11）**：开发已在 `collectors/base.py` except 分支补降级留痕（`130ccf7`），复测 stdout 出现 `[source] 故障源 不可用：凭证无效 (HTTP 401)`，28 条回归全绿（E-12），G5 / C2 改判通过。

#### ③ G3-① / C3 —— 未映射账号「不丢弃」做到了，「告警」没做到（证据 E-08）

构造一个不在 `MEMBER_DISPLAY_NAMES` 内的账号（王五）跑主流程：**没有被丢弃**（计入独立成员、条目保留），但 **stdout 完全为空**，检索「未映射 / 未登记 / 未知 / 未配置」全部为 False。推送侧同样静默——`resolve_recipients("王五")` 返回 0 个收件人，无任何提示，而 `push/members.py` 的 docstring 明写「未知成员不报错 —— 只在日志里提示」，实现未落地。

**两条链路行为不一致**：Actions 侧 `scripts/notify_push.py` 有 `warn()` 输出 `::warning::身份未映射`（第 1 周 TC-03 已验），主流程 CLI 侧完全没有。C3 的三项期望中「未映射显式告警」未达成，故与 G3-① 一并判不通过。

**改判（2026-11-11）**：开发已在 `push/members.py` 补告警（`130ccf7`），复测 `resolve_recipients("王五")` 输出 `[push] 身份未映射：王五 不在 MEMBER_EMAILS 中，跳过该成员的个人日报`，与 Actions 侧口径一致（E-12），G3-① / C3 改判通过。

#### ④ G3 判通过的前提（证据 E-10）

真实仓库 10 条提交共 7 种身份组合（方赫一人占 4 个：20233046方赫 / fh0709 / 方赫 / fh）。**不配置 `MEMBER_DISPLAY_NAMES` 时**，系统输出 7 名「成员」，方赫被拆成 4 份、于悦与杨佳莹显示为登录名；**配置后**归一为 4 人 10 条（方赫 7 条）。
即：G3 的成立**依赖配置项**而非纯代码保障。配套发现——`.env.example` 未包含 `MEMBER_DISPLAY_NAMES` 键，照模板配置永远配不出归并规则，属模板缺陷。

#### ⑤ 环境约束：飞书采集源不可用（证据 E-11）

`FEISHU_APP_ID/SECRET` 换取 `tenant_access_token` 返回 **21001（租户资质限制）**，design 0.5 已记载该错误码语义。后果：团队日报实际只有「代码提交」一类来源，「任务进展」「群内消息」恒为空；C1 / G1 的三源合计只能用 mock 数据与桩注入覆盖，无法在真实环境复现。推送侧不受影响——Webhook 投递实测 code=0（E-09）。

#### ⑥ 已知局限（不计入失败）

同一 `record_id` 重复注入会重复计数（3 条注入 → 3 条，a1 计 2 次），未按 record_id 去重。design 2.1 已写明 `record_id` 是「未来去重与对账的键」，属 v1.1 范围，不作为 C5 失败依据（C5 原文只要求「同日重跑记录数不变」，已通过）。证据 E-07。
