## 报告摘要

本报告收口第 1 周的候选调研（docs/技术栈候选清单.md，只列不定），结合第 1～2 周全部实测证据，对 10 个技术关注点逐项做出取舍；结论已在 design 0.5.1 §4 以 ADR-101～104 定稿。核心结论有四条。

第一，HTTP 客户端维持 httpx 直连不引 SDK、存储用标准库 sqlite3 加 UNIQUE 幂等、采集容错用异常驱动降级不重试、推送触发用 GitHub Actions 并以 github.actor 归属（ADR-101～104）；其余六个关注点维持现状零新增依赖。

第二，每项决策都有实测支撑：Actions 到飞书连通性 PoC（HTTP 200 / code=0）、12 次真实推送 0.87～1.81 秒、假 token 降级注入不中断、4 封邮件加 1 条群消息真实送达、34 项采集断言实跑 34/34（见第 3 章）。

第三，候选清单的 7 个开放问题已关闭 1 个（触发落点）、收敛 2 个，其余列 v1.1 或待飞书租户资质恢复，不阻塞本期验收（见 4.3）。

第四，证据缺口如实交底：6 条缺口闭合 1 条，其余保留「未核实」标注；「未核实」不影响任何 ADR，因为各项决策均不依赖活跃度数据（见 5.3）。

## 第1章 调研背景与范围

### 1.1 调研背景与目标

本组开发「智能日报生成器」：一条命令把四名成员的 GitHub 提交、飞书任务与群消息按日聚合成个人与团队两份日报，落库 SQLite 并推送邮件与群消息，另有一条与主线隔离的实时提醒支路。

第 1 周（候选收集阶段）的结论记录于《技术栈候选清单》（于悦，2026-11-09），该文档执行「只列不定」纪律：10 个技术关注点各列候选，全文不出现推荐表述，并把 7 个开放问题明确留给第 2 周以 ADR（架构决策记录）定案。本报告是第 2 周的收口：把候选清单中的事实与第 1～2 周的全部实测证据合并，逐项做出取舍——选型结论已在 `specs/design.md` 0.5.1 §4（ADR-101～104）定稿，本报告负责给出「候选事实 → 实测验证 → 决策」的完整可追溯链条。

调研要回答的问题只有一个：在 proposal 0.4.2 的范围与红线内，每个技术关注点**用什么、不用什么、为什么、什么时候重议**。

### 3.3 实时提醒通道持续实测

实时提醒支路上线后按真实 dev 推送持续观测，四项结论均有证据文件：

- **送达时延**：最近 12 次真实 dev 推送全部 code=0，单次飞书 HTTP 往返 0.87～1.81 秒（证据 W1-E-01）；
- **分支过滤**：branches 过滤 main+dev 后，docs/ 类分支的推送不再触发群消息（W1-E-04）——不过滤会把群消息刷成 git 事件流水账，是实测踩到的坑，已写进 ADR-104 决策②；
- **中文署名与归属**：四成员显示名经 github.actor 查 MEMBER_DISPLAY_NAMES 映射全部正确（W1-E-02）；
- **未映射告警**：身份不在映射内时，Actions 侧打 ::warning:: 告警、本机侧打 [push] 身份未映射并跳过该成员，两端口径一致（W1-E-03；E-12 验证 2 复核）。

### 4.4 与竞品路线的差异

## 第5章 风险与约束

### 5.1 已识别风险与缓解

本节汇总本组已识别的四项技术风险、对应实证与缓解手段（见表 5-1）。

**表 5-1　风险清单**

| **风险** | **实证** | **缓解** | **残余风险** |
| --- | --- | --- | --- |
| GitHub API 国内可达性波动 | E-04：本机 hosts 指向 127.0.0.1，TLS 被中间人替换，报 CERTIFICATE_VERIFY_FAILED | 仓库备 GitHub 访问诊断与代理指引；真实发送场景注入系统证书库（truststore） | 属网络问题非客户端问题，换 SDK 不解决（ADR-101 论证⑤） |
| 飞书自建应用租户资质 | E-11：code=21001，采集侧恒不可用 | 降级链兜底（local-git）；桩注入覆盖契约断言（E-12 验证 1） | 真实飞书数据待资质恢复（TK-303/304 按降级取证方式执行） |
| Actions Secrets 凭证泄露面 | 红线：秘密级变量绝不进仓库 | .gitignore 加 Actions Secrets 加推送前敏感信息扫描；日志只打源名与错误摘要 | 扫描器漏报（TK-901 敏感信息扫描落地后复核） |
| 境外 runner 可用性 | 3.2 与 3.3 实测通过，但环境与凭证变更可能失效 | ADR-104 写明回退路径：本机计划任务一行对接 | 需随环境变更定期复核 |

### 5.2 技术约束（红线）

1. **凭证分级**：秘密级（GITHUB_TOKEN、飞书应用凭证、Webhook 签名密钥、SMTP 授权码、成员真实邮箱）绝不进仓库；可入库级仅 MEMBER_DISPLAY_NAMES（design 5.2）。
2. **单一 HTTP 栈**：全部出站调用统一 httpx，不引入第二套（ADR-101）。
3. **启动纪律**：必须经 uv run --env-file .env 启动，直接 python -m 不读 .env 会静默降级。
4. **失败语义分层**：采集层缺凭证抛 SourceUnavailableError（运行时可降级），推送层缺凭证抛 ValueError（部署时通道不挂载），两种异常不可互换、不可合并捕获（design 5.2 纪律 1）。
5. **平台可迁移**：代码不依赖 Windows 特性，可迁移 Linux；Python 3.13；路径用 pathlib。
### 5.3 证据缺口现状

《技术栈候选清单》第七节的 6 条缺口，本报告逐条交底：

1. 候选库当日版本号、star 数未核实——仍开放；全文「未核实」标注继续有效，但不推翻任何 ADR（各项决策均不依赖活跃度数据）。
2. 含 C/Rust 扩展候选对 Python 3.13 的官方支持未逐一核对——仍开放；因本期全部维持现状、未实际引入，风险未触发。
3. lark-oapi 是否封装 user_access_token 授权——仍开放；ADR-101 已注明不作为决策依据。
4. openai／anthropic 官方 SDK 底层是否 httpx——仍开放，与开放问题 1、2 一并列 v1.1。
5. Actions 到飞书连通性——已闭合（3.2 节，run 42587824934）。
6. Aiscribe 零三方依赖的核实深度——仍开放；仅影响竞品对照精度，不影响选型结论。
### 5.4 触发重议的观察点

四项 ADR 各有明确的重议条件（表 4-1 末列），满足即重开对应决策，无需整份调研重做。除此之外，两个外部事件会触发整份调研重开：其一，飞书租户资质恢复——开放问题 4 重启，飞书采集候选（表 2-2）重新对比；其二，产品确认接入 AI 摘要——开放问题 1、2 重启，LLM 候选（表 2-5 末行）重新对比。
