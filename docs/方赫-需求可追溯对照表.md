## 一、填写口径

1. 每行只填**事实与编号**，不复制 proposal 原文；所有 S / N / C / TK / UC 编号真实存在，不新造编号。
2. 「设计 / 类·表」列回指 `specs/design.md` 的数据模型、接口契约，或 `daily_reports` / `WorkItem` 等实体。
3. 「代码与证据」列写仓库内可点开的路径；标注「✅ 已实测」的须有文档或 run 编号支撑，没有的一律写 `⚠️ 待补`。
4. 状态列：`✅ 一致` / `⚠️ 有待补项（写明差在哪、由哪个 TK 承接）` / `— 不适用`。
5. 填完用 `specs/tasks.md` §12 覆盖矩阵逐行核对：每条 S 有 TK 承接、每条 C 有验收锚点、每条 N 有守卫。
6. 阶段评审会三问：需求怎么落到用例？用例怎么落到任务与类/表？成功标准怎么落到可观测证据？——本表就是答案。
