## 正文（约 200 字）

**触发描述**在 `SKILL.md` 第 3 行 frontmatter：`Use when executing an implementation plan in the current session as the implementer yourself — your human partner chose inline execution, or no subagent tool is available`。只给条件不给步骤，「人选了同会话执行」或「没有子代理工具」命中才挂载，把「谁来实现」写进路由，描述即开关。

**工作步骤**由 Core principle 定调：计划已完成思考，只照做、逐步用亲见的失败再转绿证明、留下扛得住上下文压缩的记录。Setup 建 worktree 与 `progress.md` 台账、预检任务间 Interfaces 冲突、强制先挂 TDD；循环为 `task-start` 取 brief + BASE → 比对每个 `Expected:` → commit → 完成契约（测试亲跑、偏差写 `Ruling: 决定—理由—错了的代价`）→ `task-done`；末尾整支线一次全新上下文评审，Critical/Important 一轮 RED→GREEN 修复，Minor 只入台账。中途不问人，仅破坏性、安全敏感、worktree 外副作用、计划全靠猜四类才停。

**配套**无 `references/`，只有两个脚本且都转调 `../subagent-driven-development/scripts/`，复用同一 workspace 与 ledger。`task-start` 一次调用抽 brief 并记 `git rev-parse HEAD` 为 BASE（注释写明少一次调用就少一轮重读上下文）；`task-done` 跑测试、全量输出落 `task-N-tests.log`、仅退出码 0 才追加 `Task N: complete (commits … tests: …)`——「台账只记真跑过的」被固化成命令。判断类长尾收在 12 行 `Common Rationalizations` 借口表。

## 一句话结论

它省掉的不是「执行」，而是**每任务的新鲜上下文与第二双眼睛**：用 brief 当规格、ledger 当记忆、TDD 当每任务门禁、末尾整支线终审当第二双眼睛逐项换回；也正因如此，台账必须落在文件里而非会话里——与我们 `docs/` 中「记录要能追溯、不能靠记忆」是同一个道理。
