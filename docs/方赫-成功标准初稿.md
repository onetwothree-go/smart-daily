## 二、8 条可度量指标（含定稿数值）

| 编号 | 指标 | 度量方式 | 目标值 | 判定口径 |
|---|---|---|---|---|
| S1 | 送达时延 | 从本地 `git push` 返回到飞书群出现提醒，用 Actions run 的 `created_at` 与群消息时间戳计时，实测 3 次 | **≤ 60 秒，3/3 次通过** | 超时或漏发 1 次即不通过 |
| S2 | 显示名正确率 | 4 名组员各用自己账号向 `dev` 推 1 次，逐条检查群消息署名 | **中文名 4/4 = 100%** | 出现 1 个原始登录名或「身份未映射」告警即不通过 |
| S3 | 未映射身份 | 用不在 `MEMBER_DISPLAY_NAMES` 中的账号向 `dev` 推 1 次 | **显示原始登录名 + Actions 日志出现告警，且记录不丢失** | 静默丢记录即不通过（回落与告警各 1 次） |
| S4 | 分支过滤 | 在 `feature/*` 分支 push 1 次 | **群内提醒 0 条，notify 工作流不触发** | 出现 1 条即不通过 |
| S5 | 关键词 / 签名 | ①去掉提醒正文「日报」二字推 1 次；②填错 Secret 推 1 次（改完必须还原） | **① `code=19024` ② `code=19021`；2/2 Actions 亮红灯** | 静默成功、不报错即不通过（脚本约定不静默、不重试） |
| S6 | 周末触发 | 周六、周日各向 `dev` 推 1 次 | **2/2 正常触发** | 验的是代码里没有 weekday 判断、不漏发 |
| S7 | 刷屏口径 | 一次 push 带 **5 个 commit**，数群消息条数 | **1 条**（定稿口径：一次 push 汇总为 1 条消息，正文列出 5 个提交） | 多于或少于 1 条均不通过 |
| S8 | 汇总独立 | 实时提醒后查 SQLite 与当天 22:00 汇总日报 | **实时提醒入库 0 条；日报条目数差异 0；22:00 日报内容不变** | 实时提醒污染日报数据即不通过 |

**数值依据**：S1 取 60 秒是 GitHub Actions 排队 + 安装 httpx 的常规上限（现有 4 次 run 均 success）；S7 的「1 条」来自 `scripts/notify_push.py::build_text` 的实现——它按 `len(commits)` 生成**一条**汇总文本，不按 commit 逐条发。其余为目标口径的直接量化，非拍脑袋估值。

## 三、度量约定

- 数据来源以 **git 仓库、CI 输出、飞书返回码、测试报告**为准，不接受口头声明
- 每条用例按 `docs/testing/用例执行记录-第1周.md` 记满 **8 个字段**（用例编号 / 前置条件 / 步骤 / 期望结果 / 实际结果 / 通过与否 / 日期 / 执行人），**当天记录，不得事后补写**
- 跑 S2 前必须先确认 `MEMBER_DISPLAY_NAMES` 已含 4 人全部登录名/别名（当前 8 条，含 `zhaorui715:赵蕊`、`fh0709:方赫`），否则会白跑
- S5 属于破坏性验证，须在群里报备并及时还原配置
- 每周例会核对一次，偏差 > 20% 的指标须在周报说明原因；指标变更须组内全员同意并记入本文件变更记录
