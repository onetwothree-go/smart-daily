## 方案一：daily-report（开源 CLI 工具）

**定位**：命令行日报生成器——自动发现 GitHub 活动并生成可直接发 Slack 的 standup 摘要。

### 功能模块
- **PR 自动发现**：跨所有仓库发现"我创建的 / 我贡献的 / 我评审的"三类 PR
- **双引擎混合**：本地 git 历史（快）+ GitHub GraphQL API（全）可切换/混用
- **Slack 推送**：webhook 直接发到频道
- **PPT 导出**：`--slides` 生成 sprint review 幻灯片（每项目一页）
- **AI 摘要**：`--consolidate` 调用 Claude 生成自然语言总结

### 核心流程
```
本地 git log + GitHub GraphQL → PR/commit/issue 归集 →
按日期范围筛选 → （可选）LLM 摘要 → Markdown/Slack/PPTX 输出
```

### UI 与交互
纯 CLI，无图形界面。参数驱动（--date/--from/--to/--org/--user/--repos-dir），
面向开发者，零学习成本但仅适合技术用户。

### 对我们的参考价值
- ✅ 最接近本项目形态：git 数据源 + 自动归集 + 推送，架构思路可直接对照
- ✅ "本地 git + API 双引擎"印证了我们采集层"多源降级"的设计（local-git 源是合理兜底）
- ⚠️ 仅覆盖 GitHub 单一数据源，无任务系统、无群聊、无团队日报汇总——正是我们要补的缺口

## 方案二：DevDiary（开源 + LLM 摘要）

**定位**：个人开发者"日记"助手——扫 git 提交，用本地 LLM 生成 stand-up / 周回顾。

### 功能模块
- 多仓库 git 提交扫描（可按项目筛选）
- 日/周/月/自定义时间范围
- 本地 LLM 摘要（Ollama + LLaMA 3，**本地推理**）
- 无关文件过滤（venv/.git/pycache）
- CLI + Streamlit 双形态（有图形界面）

### 核心流程
```
扫描 git commits → 过滤无关变更 →
（可选）本地 LLM 转写自然语言 → 文本文件输出 / Streamlit 页面查看
```

### UI 与交互
CLI 为主 + Streamlit 网页界面，适合个人自用；界面简单，输出为纯文本/journal 风格。

### 对我们的参考价值
- ✅ "本地 LLM 摘要"是隐私敏感场景的备选路线（我们项目用 API，但报告里可作为对比项）
- ✅ 印证了"commit message → 自然语言"必须经 LLM 转写这一核心环节
- ⚠️ 纯个人工具：无多成员、无团队汇总、无推送渠道——再次确认"团队日报"是差异化点
- ⚠️ 依赖 Ollama 本地部署模型，普通用户门槛高

## 方案三：Teambition AI 智能周报（商业成品）

**定位**：钉钉旗下项目管理工具内置的 AI 周报能力——"商业软件路线"的代表。

### 功能模块
- **智能周报**：自动生成个人周报，从任务内容生成动态摘要、评论摘要、执行建议、风险评估
- **风险预判**：从数据中预判风险、定位问题
- **数据洞察**：自然语言提问生成数据报告、图表化呈现
- 与钉钉群聊/文档/审批打通

### 核心流程
```
任务数据（Teambition 内）→ AI 摘要 + 风险分析 →
生成周报 → 保存为钉钉文档分享
```

### UI 与交互
完整 SaaS 产品，图形界面，与钉钉生态深度集成，开箱即用。

### 对我们的参考价值
- ✅ "自动周报 + 风险预判"验证了市场需求的真实性（商业公司已在做）
- ⚠️ 数据锁定在自家生态：只用 Teambition 的任务数据，**不采集代码提交**——研发团队的真实工作量（代码）反而看不到，这是商业成品 vs 我们项目的核心差异
- ⚠️ 黑盒：用户无法定义采集范围和条目粒度；我们的开源+可配置是差异点

## 三方案横向对比（业务调研报告第 4 章素材）

| 维度 | daily-report | DevDiary | Teambition AI |
| --- | --- | --- | --- |
| 数据源 | GitHub（git+API） | 本地 git | 自家任务系统 |
| AI 摘要 | Claude API | 本地 Ollama | 商业黑盒 |
| 团队日报汇总 | ❌ | ❌ | 部分（项目维度） |
| 推送渠道 | Slack | 无 | 钉钉文档 |
| 代码提交纳入 | ✅ | ✅ | ❌ |
| 开源可配置 | ✅ | ✅ | ❌ |
| 上手门槛 | 低（CLI） | 高（需 Ollama） | 低（SaaS） |

**共性结论**：三者都验证了"自动归集 + AI 摘要"的技术路线成立；但**没有一个同时做到：
代码提交 + 任务 + 群聊三源采集、个人日报 + 团队汇总、可配置的开源方案**——这就是本项目的定位空间。
