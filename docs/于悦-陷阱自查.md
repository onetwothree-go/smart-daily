做 XIAORUI 智能教育平台和建检智通时，我的用法基本是：把想法丢给 AI，能跑就收。对照第 1 章才发现五个陷阱全踩了。

1. **需求蒸发**：「豆包调用失败重试 2 次、单次超时 60 秒」这条规则只写在 `doubao_ai.py` 的参数里，需求文档《基于人工智能的自适应学习平台.docx》一个字没提，现在连"为什么是 2 次"都想不起来了。

2. **不可审查（最疼）**：AI 生成的 `doubao_ai.py` 把豆包 API key 硬编码在第 11 行，当时只验收"能不能跑"，没人审过代码，密钥就这么跟着文件进了备份。

3. **不可复现**：`backend/` 下 `venv` 和 `.venv` 两套虚拟环境并存——环境崩过重搭过，哪套是活的要靠猜。

4. **不可维护**：Python 后端里躺着一份 npm 的 `package.json`，AI 顺手生成的，没人删；数据库有 `xiaorui_full_system.db` 和 `xiaorui_learning.db` 两个，代码用前者，后者没人敢动。

5. **上下文漂移**：XIAORUI 桌面一份、D 盘一份，D 盘那份多出 `generated_questions/` 目录，哪份是最新说不清，AI 换了个拷贝接着写，两边已经互相矛盾。

这五条这周靠「规范先行」接住：proposal 写清范围和不做什么，密钥一律走环境变量，先规范后让 AI 动手。
